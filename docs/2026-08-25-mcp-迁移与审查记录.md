# MCP 迁移与代码审查记录

日期：2026-08-25
范围：将 NAO 的 MCP 对外能力迁移至 Personal Data Agent，供 Codex 等 MCP 客户端调用。

## 变更目标

NAO 通过 Streamable HTTP 的 `/mcp` 端点将其分析代理、上下文层和故事能力提供给外部 agent。本次实现为 data agent 建立等价的受控入口：外部 agent 使用 MCP 协议调用，但仍复用本系统既有的用户隔离、只读 SQL 保护、业务上下文和报表模型。

## 已实现内容

1. 新增 `POST /mcp`。它处理 MCP 的 `initialize`、`tools/list` 和 `tools/call` JSON-RPC 请求，并在初始化时返回 MCP session id。
2. 新增 `POST /mcp/tokens`。已登录用户可获取包含 `aud=mcp` 的 Bearer JWT；默认有效期为 90 天，可由 `MCP_TOKEN_TTL_DAYS` 调整。
3. MCP 默认关闭。只有部署者显式设置 `MCP_ENABLED=true` 后端点才可用；代理、上下文和报表三组工具亦可分别通过环境变量控制。
4. 子代理模式：`ask_data_agent` 会创建或续接系统聊天，调用完整的模型工具循环，并保存问题、回答和工具事件。
5. 上下文层模式：`execute_sql` 复用现有单条只读 `SELECT`/`WITH` SQL 防护；`grep` 查询用户上下文文档；`ls` 枚举该用户可用的上下文、文件和数据库连接。
6. 报表模式：提供 `list_reports`、`get_report`、`create_report`、`update_report` 和 `archive_report`。归档字段通过增量迁移加入，正常列表会排除已归档报表。
7. 不提供 MCP 的永久删除报表能力，避免外部 agent 触发不可逆删除。

## 权限与数据边界

- Bearer token 只携带用户 id，服务端在每个 MCP 请求中重新读取该用户；所有文件、连接、聊天、上下文、查询结果和报表均按 `user_id` 查询。
- `execute_sql` 只能选择该用户的一个文件或一个已保存连接，不能通过伪造 id 跨用户读取数据。
- SQL 实际执行仍由现有 SQL guard 负责，MCP 不绕过只读事务和行数上限。
- MCP 默认关闭，避免升级部署后自动暴露数据接口。

## 审查结论

结论：可提交，核心隔离和只读约束未被 MCP 旁路。

已检查：

- JSON-RPC 初始化、工具列表和工具调用的响应结构；
- 未提供 Bearer token 或 MCP 未启用时，端点拒绝访问；
- 外部工具按开关暴露；
- 归档采用可恢复的状态变更，而非删除；
- `git diff --check` 无空白错误。

自动化验证：容器内执行 `pytest -q`，结果为 `10 passed`。新增测试覆盖 MCP 显式启用、token 生成、初始化、工具发现，以及默认关闭时的拒绝访问。

## 后续风险与建议

1. 当前 token 为无状态 JWT，泄露后只能等待过期或轮换 `APP_SECRET_KEY`，不能单独吊销。生产部署建议后续增加 token 表、token id（jti）和撤销接口。
2. 目前测试尚未覆盖真实 MCP host（例如 Codex）与 `tools/call` 的端到端互操作；发布前宜在已启用 MCP 的测试栈中做一次实际客户端连通性测试。
3. `POST /mcp` 对格式错误的 JSON 会返回 401；后续可以区分认证失败和 `-32600 Invalid Request`，使 MCP 调试更清晰。

## Codex 接入摘要

启用 `MCP_ENABLED=true` 并重启 API，登录 data agent 后请求 `POST /mcp/tokens` 获取 token。在 Codex 中添加 Streamable HTTP MCP server：URL 为 `http://localhost:8000/mcp`，请求头为 `Authorization: Bearer <token>`。请不要共享 token。
